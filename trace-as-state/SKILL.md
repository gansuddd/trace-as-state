# Trace as State (TaS) 两阶段长文本深度推演技能

本技能通过“先遣摸排草稿 $\to$ 状态前置置顶 $\to$ 终审定向重读”的两阶段执行机制，解决大模型在阅读超长文本或处理复杂逻辑时容易盲目遗漏、推导失焦的问题。

## 适用场景（何时使用）

当遇到以下任务，或用户显式输入 `/trace-as-state` 时触发：
- **超长文档/论文深度理解**：对数万字长文、规范白皮书进行细节挖掘与深层推导；
- **复杂多跳与关系推演**：涉及跨多个实体、调用跳转、深层因果追溯的复杂问题；
- **大型代码库跨模块排查**：需在多个文件或长日志中排查竞态、逻辑漏洞、隐蔽依赖；
- **用户显式要求**：“深度分析”、“两轮前置重读”、“用 TaS 范式推导”。

---

## 核心执行流程（SOP）

### 步骤 1：派发先遣子代理独立摸排（Pass 1）

主 Agent 调用 `invoke_subagent`，启动一个只读探索子代理（`TypeName: "research"` 或 `TypeName: "self"`），在干净独立的后台环境中通读目标材料。

**子代理 Prompt 模板**：
```markdown
你现在作为先遣探索员。请通读目标材料并深入推导指定问题。

【重要输出要求】：
1. 必须详尽输出你的完整推导草稿与思考过程：
   - 尝试过的分支与思路；
   - 锁定的关键线索、代码行号与定位依据；
   - 排除掉的错误假设与死胡同；
   - 初步推断的结论。
2. 严禁只给简短结论！本轮核心在于提供探索过程中的关键推演状态。
```

---

### 步骤 2：主 Agent 截取草稿并封装状态块

子代理返回后，主 Agent 提取其思考草稿，执行清洗与防护封装：

1. **5 万字硬截断**：若草稿超过 50,000 字符，截取前 50,000 字符并追加 `...`，防止上下文溢出；
2. **剔除裸露答案**：只保留推演过程和依据，不留现成结论，促使第二轮独立复核；
3. **注入防思维惯性警示语**：强制添加警示标语，防止模型盲信初探草稿。

**标准前置状态块模板**：
```markdown
<first_run_reasoning_traces>
[重要提示与纠错警示]
以下内容为系统初探生成的推导草稿，极可能包含推断漏洞或未排除的假说。
请仅将此草稿作为排查线索参考！在接下来的阅读中，必须对照原文严格挑刺核验，严禁盲信草稿！

[初探思考草稿]
{截断并清洗后的推导草稿}
</first_run_reasoning_traces>
```

---

### 步骤 3：状态前置定向复审与求解（Pass 2）

主 Agent 亲自带状态进行第二轮高精度重读。

> [!IMPORTANT]
> **输入排布铁律**：
> **`[前置状态块] + [原始文本主体] + [末尾具体问题与输出格式约束]`**
> 具体问题与格式要求必须始终紧贴在全文本的最末端，确保读完全文后注意力重新锚定在最终交付上。

**主 Agent 复核心法**：
1. **定向核验**：拿着草稿中指出的可疑节点/行号，直奔原文对应位置交叉核验；
2. **纠偏纠错**：检查初探草稿是否看漏了边界约束、转折逻辑或反例；
3. **确定结论**：基于原文真实证据，修正错误假说，得出高度确凿的结论。

---

### 步骤 4：主会话直接交付

主 Agent 直接在当前主对话中输出经过验证的最终答案。由于主 Agent 亲自完成了第二轮精读，完整保留了对细节的记忆，可无缝承接用户的任何后续追问。

---

## 避坑准则（Do's and Don'ts）

- **必须物理隔离**：第一轮摸排必须由独立子代理在后台完成，严禁在主窗口自问自答（否则历史注意力矩阵会被第一轮错误污染）。
- **禁止无关草稿**：必须针对当前任务由子代理真实探索，严禁使用预设的通用假草稿（无关草稿会导致严重幻觉）。
- **必须带警示语**：前置状态块中必须包含防盲信警示，迫使模型保持审判与挑刺视角。
